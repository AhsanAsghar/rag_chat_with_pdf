# 📚 Chat with Your PDF/Notes — RAG Application

Upload a PDF (or `.md`/`.txt` notes), then ask questions about it in a chat interface. Answers are generated by an LLM but **grounded in your document's actual content** using Retrieval-Augmented Generation (RAG) — with source citations showing exactly where each answer came from.

---

## 🧠 How it works

```
Upload PDF/notes
      │
      ▼
Extract text (page by page)
      │
      ▼
Split into overlapping chunks
      │
      ▼
Generate embeddings for each chunk (OpenAI)
      │
      ▼
Store in local vector database (ChromaDB, persisted to disk)
      │
      ▼
── You ask a question ──
      │
      ▼
Embed your question → find the most similar chunks
      │
      ▼
Send question + retrieved chunks to the LLM
      │
      ▼
Grounded answer + source citations shown in chat
```

## ⚙️ Setup

### 1. Install dependencies
It's recommended to use a virtual environment:
```bash
python -m venv venv
source venv/bin/activate      # On Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### 2. Add your OpenAI API key
Copy the example env file:
```bash
cp .env.example .env
```

Open `.env` and set your key:
```
OPENAI_API_KEY=sk-your-actual-key-here
```

> Get a key at: https://platform.openai.com/api-keys
> You'll need billing enabled on your OpenAI account — this app uses both the **embeddings** endpoint and the **chat completions** endpoint, which are billed separately (both are very cheap for typical usage — a few cents per document + question).

The rest of `.env` has sensible defaults, but you can tune them:

| Variable | Default | What it controls |
|---|---|---|
| `OPENAI_API_KEY` | *(required)* | Your OpenAI key |
| `LLM_MODEL` | `gpt-4o-mini` | Model used to generate answers |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Model used to embed chunks/questions |
| `CHROMA_PERSIST_DIR` | `./data/vector_db` | Where the vector database is stored on disk |
| `CHUNK_SIZE` | `2000` | Characters per chunk (~500 tokens) |
| `CHUNK_OVERLAP` | `200` | Overlap between chunks (~50 tokens) |
| `TOP_K` | `4` | Number of chunks retrieved per question |
| `UPLOAD_DIR` | `./data/uploads` | Where uploaded files are saved |
| `MAX_UPLOAD_SIZE_MB` | `25` | Max file size accepted |
| `BACKEND_URL` | `http://localhost:8000` | Used by the frontend to reach the backend |

## ▶️ Running the app

You need **two terminals** — one for the backend API, one for the frontend UI.

### Terminal 1 — start the backend
```bash
uvicorn backend.main:app --reload --port 8000
```
This starts the FastAPI server at `http://localhost:8000`.
You can view the interactive API docs at `http://localhost:8000/docs`.

### Terminal 2 — start the frontend
```bash
streamlit run frontend/app.py
```
This opens the chat UI in your browser (usually `http://localhost:8501`).

### Using it
1. In the sidebar, upload a PDF (or `.md`/`.txt`) and click **Ingest document**
2. Wait for the "Successfully ingested..." confirmation
3. Ask a question in the chat box — the answer will include an expandable **Sources** section showing which document/page it came from

## 🔌 API Endpoints (backend)

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/upload` | Upload and ingest a document (multipart file upload) |
| `POST` | `/ask` | Ask a question — returns answer + source chunks |
| `GET` | `/documents` | List all ingested documents |
| `DELETE` | `/documents/{document_id}` | Remove a specific document |
| `POST` | `/reset` | Wipe all documents and embeddings |

Full interactive docs (with request/response schemas) are auto-generated at `/docs` once the backend is running.

## 🛠️ Troubleshooting

| Problem | Fix |
|---|---|
| `OPENAI_API_KEY is not set` error on startup | Make sure you copied `.env.example` to `.env` and filled in a real key |
| `No extractable text found in this PDF` | The PDF is likely scanned/image-only and needs OCR, which isn't supported here — try a text-based PDF |
| Frontend shows "Could not reach backend" | Make sure `uvicorn backend.main:app --reload --port 8000` is running in another terminal |
| Answers seem generic / not grounded | Check the **Sources** panel — if similarity scores are low, try rephrasing the question, or the document may not contain that information |
| Slow ingestion on large PDFs | Expected — embedding many chunks takes time. Consider splitting very large PDFs before uploading |

## 🧩 Extending this project

- **Multi-document chat**: already supported via `document_ids` filter in `/ask` — add a document picker in the frontend
- **Swap vector stores**: all Chroma calls are isolated in `vector_store.py` — swap for FAISS/Pinecone by rewriting just that file
- **Swap LLM providers**: `llm_client.py` and `embedder.py` are the only two files that call OpenAI — swap for Anthropic/Claude or a local model there
- **Streaming answers**: OpenAI's chat completions support streaming; update `llm_client.py` and the Streamlit UI to render tokens as they arrive
- **Re-ranking**: add a re-ranking step in `retriever.py` before passing chunks to the prompt builder, for higher-precision retrieval
